# 03. PDF 페이지를 ForScore 방식으로 하나의 라이브러리 항목으로 묶기

- **커밋:** `45f5075f0b0420df4ad87305a1007d9c9eb35556`
- **날짜:** 2026-09-09

## 배경 / 문제

PDF 5페이지를 스캔하면 스캔 직후 리뷰 화면에서는 페이지 넘기기가 되지만, 라이브러리에 저장한 뒤 다시 열면 5개의 서로 무관한 곡으로 흩어져 있고 페이지 넘기기 기능도 사라지는 문제. ForScore처럼 한 PDF는 하나의 항목으로 유지되어야 한다는 요청.

## 변경 내용

- `Song` 타입에 `groupId`(같은 문서의 페이지들이 공유하는 id)와 `pageNumber`(1부터 시작하는 페이지 순번) 필드 추가.
- `ScanScreen`의 PDF 래스터라이즈 과정에서 여러 페이지짜리 PDF일 때만 `groupId`를 부여하고, 페이지 제목에서 중복되던 `(n/m)` 표기는 제거 (페이지 넘김 바가 이미 표시하므로).
- `buildSongFromOcr`/`buildSongsFromPages`가 `groupId`/`pageNumber`를 그대로 song에 반영.
- `LibraryScreen`에서 `groupId` 기준으로 묶어 **한 행**으로 표시(제목 + "N페이지"), 선택 시 그룹의 모든 페이지를 `pageNumber` 순으로 정렬해 페이지 넘김이 가능한 에디터로 진입.
- 그룹 삭제 시 모든 페이지를 한 번의 확인으로 함께 삭제 (`deleteSongs` 배치 함수 신설).

## 검증

- 타입체크·전체 테스트 통과.
- 웹 빌드에서 다중 페이지 스캔 → 배치 리뷰 목록(페이지 표기 포함) → 라이브러리에 한 항목으로 저장되는 흐름을 코드 레벨에서 점검. 실제 다중 페이지 PDF로 라이브러리 재진입 시 페이지 넘김이 복원되는지는 이후 실기기 확인 필요 항목으로 남김.
