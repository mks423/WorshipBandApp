# 02. 라이브러리 퍼시스턴스 추가, API 키 문서화, 가로모드 허용

- **커밋:** `a603da3a75499f0dd7d90a3c3ef14579e6f86339`
- **날짜:** 2026-09-09

## 배경 / 문제

전체 코드베이스 점검 중 발견한 3가지 이슈:

1. **퍼시스턴스 없음**: 스캔·수정한 곡이 `App.tsx`의 `useState`에만 존재해, 앱을 껐다 켜면 전부 사라짐.
2. **Google Vision API 키 노출 위험**: `EXPO_PUBLIC_` 접두사 값은 앱 번들에 그대로 포함되는데, 문서에는 "Vision API로 사용 범위 제한"만 안내되어 있고 "어떤 앱이 이 키를 쓸 수 있는지" 제한하는 애플리케이션 제한(Bundle ID)은 언급이 없었음.
3. **세로 화면 고정**: 아이패드를 보면대에 놓고 쓰는 용도에 맞지 않을 수 있음.

## 변경 내용

- `src/features/library/` 신설: `AsyncStorage` 기반으로 곡 목록을 저장/조회/삭제.
- 앱의 첫 화면이 "내 악보" 라이브러리 홈 화면으로 바뀜. 스캔은 "새로 스캔하기"를 눌러야 진입하는 명시적 액션이 됨.
- 카메라/파일로 가져온 이미지의 URI는 OS가 관리하는 임시 캐시 경로라 재실행 시 무효화될 수 있어서, 저장 시점에 앱 전용 영구 디렉토리(`Directory(Paths.document, "wba-sources")`)로 복사하도록 처리 (`ensureDurableImage`).
- 구현 중 실제 크래시 하나 추가 발견: `Directory`/`Paths` 객체를 모듈 최상단에서 즉시 생성했더니 웹에서 `validatePath is not a function`으로 앱 전체가 죽음 → 지연 초기화(lazy init)로 수정.
- README에 애플리케이션 제한(iOS Bundle ID) 관련 안내 보강. 단, Bundle ID 자체는 네이밍 결정이라 임의로 설정하지 않음.
- `app.json`의 `orientation`을 `"portrait"` → `"default"`로 변경.

## 검증

- 타입체크·전체 테스트(71개) 통과.
- 웹 빌드에서 라이브러리 홈 화면 렌더링 확인.
- 실제 파일 복사(카메라/문서 피커 → 영구 저장소)와 AsyncStorage 동작은 네이티브 전용이라 웹 환경에서 완전히 검증하지 못함 — 실기기 확인 필요 항목으로 남김 (→ 이후 07/08번 리포트에서 웹 저장 관련 버그가 실제로 발견됨).
