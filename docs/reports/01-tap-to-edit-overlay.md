# 01. 탭-투-에딧 코드 오버레이로 편집 흐름 전면 개편

- **커밋:** `d2f52bc711ad71cf539ff803e92520a712f9c236`
- **날짜:** 2026-09-09

## 배경 / 문제

기존에는 스캔한 악보를 텍스트 편집 폼(제목/코드/가사 입력, 줄·섹션 분할·병합)에서 고치는 방식이었다. 사용성이 떨어지고, 원본 악보와 대조하며 수정하기 번거롭다는 피드백이 있었다.

## 변경 내용

- 텍스트 편집 폼을 없애고, 곡을 선택하면 **원본 스캔 이미지 위에 인식된 코드가 그대로 겹쳐 보이는 화면**으로 바로 진입하도록 변경.
- 코드 배지를 **탭하면 수정**(확인 모달 포함), **드래그하면 위치 이동**, 빈 자리를 탭하면 **새 코드 추가**.
- 드래그가 실제로는 항상 탭으로 처리되던 **stale-closure 버그**를 발견해 수정 — `PanResponder`를 `useRef`로 한 번만 생성하면서 `scale` 값이 레이아웃 계산 전(0)인 시점에 고정되어버린 것이 원인.
- **키 변경 모달** 추가: 반음 스테퍼 + 12키 그리드로, 기존의 인라인 전조 버튼 행을 대체.
- **페이지 넘기기**: 여러 페이지짜리 PDF를 스캔했을 때 편집 화면을 나가지 않고 이전/다음 페이지로 이동 가능.
- **내보내기**: `react-native-view-shot` + `expo-print` + `expo-sharing`으로 현재 페이지를 PNG/PDF로 저장·공유.
- **버그 수정**: iOS `NSCameraUsageDescription`이 `app.json`에 없어서 카메라 권한 요청 시 앱이 강제 종료되던 문제.

## 검증

- 타입체크·전체 테스트(71개) 통과.
- Expo 웹 빌드에서 코드 탭 편집, 드래그 이동, 페이지 넘기기, 내보내기 모달까지 Playwright로 직접 구동해 확인.
- 실제 iPad 기기에서의 터치 드래그·카메라 권한 동작은 원격으로 검증 불가해 사용자에게 직접 확인 요청.
