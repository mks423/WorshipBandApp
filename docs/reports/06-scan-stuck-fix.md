# 06. 스캔 후 화면이 멈추는 버그 수정 (unhandled rejection)

- **커밋:** `d2325f0eef515283fef3d807619cf882fa7ab15c`
- **날짜:** 2026-09-09

## 배경 / 문제

사용자 리포트: "악보 스캔 후 로드가 안되네요" — 스캔하기를 누르면 스피너만 돌다가 멈추고 편집 화면으로 넘어가지 않음.

## 원인

`ScanScreen.scan()`에서 `onSongsScanned(songs)`를 **`await` 없이** 호출하고 있었다. `App.tsx`의 `handleScanned`는 (02번 커밋에서 라이브러리 저장 로직이 추가되며) `async` 함수가 되었는데, 이 호출을 기다리지 않으니 그 안에서 에러가 나도 **완전히 무시되는 unhandled promise rejection**이 됨. `ScanScreen`의 `finally { setIsScanning(false) }`는 fire-and-forget 호출이 끝나길 기다리지 않고 즉시 실행되므로, 스피너는 꺼지지만 실제 화면 전환은 조용히 실패한 채 멈춰 있었다.

## 변경 내용

`await onSongsScanned(songs);`로 수정하고, `onSongsScanned` prop 타입을 `void | Promise<void>`로 확장. 이제 저장 단계에서 에러가 나도 기존 "스캔 실패" 알림 경로로 원인이 표시된다.

## 검증

- 타입체크·전체 테스트 통과.
- 웹 환경에서 이미지 1장/2장, 큰 이미지, 연속 스캔 등 여러 시나리오로 재현을 시도했으나 실제로는 재현되지 않음 — 다만 이 수정 자체는 "에러를 삼키지 않고 표면화한다"는 점에서 원인 불문 유효한 견고성 개선.
- 이 수정 덕분에 실제 사용자 환경에서 **다음 버그(07번)의 정확한 에러 메시지가 드러나며 진짜 원인이 확인됨** — 결과적으로 이 커밋이 07/08번 버그를 진단 가능하게 만든 전제 조건이 되었음.
